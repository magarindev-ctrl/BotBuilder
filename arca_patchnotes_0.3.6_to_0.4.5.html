v0.3.6 → v0.4.5

긴 원고·Lua·CSS의 부분편집, 수정 구간 확인, 에셋 다중 삭제와 봇 아이콘 편집을 추가했습니다.

2026-10-29 · 이전 패치노트 이후 v0.4.0~v0.4.5 변경

이번 업데이트 핵심

BB는 LLM과 대화하며 캐릭터·시뮬레이션을 만드는 RisuAI / RisuBard API v3 플러그인입니다. 이번 변경도 본체 수정 없이 단일 JS 플러그인 안에서 동작합니다.

  • 부분편집: 긴 코드·원고 전체 대신 바꿀 구간만 응답하도록 요청하고, 변경 전후를 검토할 수 있습니다.
  • 구간 확인: 일반 문장의 원문이 맞지 않으면 후보를 고르거나 직접 범위를 지정할 수 있습니다.
  • 에셋 관리: 다중 선택·선택 삭제·전체 삭제를 추가했습니다.
  • charx: 에셋 합계 100MiB 출력 제한을 제거하고, 리스렐름에서 대표 이미지를 찾을 수 있도록 저장 경로를 수정했습니다.
  • 봇 아이콘: 에셋 탭에서 대표 이미지를 직접 등록·교체·해제할 수 있습니다.

v0.4.0

긴 원고·코드의 구간 부분편집

v0.3.5의 로어북 항목·필드 단위 수정에서 확장해, 하나의 긴 본문 안에서도 바뀌는 구간만 받도록 했습니다. 예를 들어 CSS 색상 한 곳을 바꾸기 위해 전체 OUT 본문을 다시 출력할 필요가 없습니다.

  • 대상: 캐릭터 설명, 첫 메시지·시작 상황 본문, 로어북의 이름·키·본문, 정규식 이름·IN·OUT, Lua 이름·코드, 기존 초기 변수 값. 설계 대화의 수정 묶음에도 같은 형식을 사용합니다.
  • 응답 형식은 schemaVersion: 2이며 문자열 대신 {edits:[{before, after}]}를 사용할 수 있습니다. 필드당 1~100개 구간을 지원합니다.
  • before는 원문, after는 교체할 내용입니다. 공백·들여쓰기·줄바꿈까지 정확히 매칭하고, 줄 번호는 검토용으로만 표시합니다.
  • 여러 구간은 모두 요청 당시 원문 기준으로 계산합니다. 구간이 겹치거나 검증에 실패하면 제안을 적용하지 않습니다. v0.4.3의 일반 문장 확인 흐름은 아래에 별도로 설명합니다.
  • 새 작성·빈 필드의 첫 작성·명시적인 전체 재작성은 완성 문자열을 사용할 수 있습니다. 수정하지 않은 항목과 필드는 보존합니다.
{
  "schemaVersion": 2,
  "task": "regex",
  "data": {
    "upsert": [
      {
        "ref": "r0",
        "rule": {
          "out": {
            "edits": [
              {
                "before": "color: #fff;",
                "after": "color: #ddd;"
              }
            ]
          }
        }
      }
    ],
    "remove": []
  }
}
LLM 출력이 구간 수정 형식을 따를 때 출력 토큰을 줄입니다. 판단에 필요한 원문 입력을 자동으로 줄이는 기능은 아닙니다. 제안은 검토 → 원고에 적용 → 본체 저장 순서로 반영합니다.

v0.4.1

에셋 다중 삭제 · charx 출력 제한 완화

  • 에셋 목록에 항목별 체크박스, 전체 선택·선택 해제, 선택 삭제·전체 삭제와 선택 개수를 추가했습니다.
  • 삭제 확인 후 현재 원고의 추가 에셋 참조를 제거합니다. 대표 이미지·감정 이미지와 공유될 수 있는 실제 파일은 유지합니다.
  • 가져온 charx의 연결된 CCv3 메타데이터도 정리해, 삭제한 참조가 남아 재내보내기를 막는 문제를 보완했습니다.
  • charx 내보내기의 에셋 합계 100MiB 제한을 제거했습니다. 확장자는 기존처럼 .charx입니다.
출력 제한 제거가 무제한 파일 처리를 보장하지는 않습니다. 브라우저 메모리·ZIP 형식·업로드 서비스의 제한은 남습니다. BB의 charx 가져오기 100MiB / 압축 해제 200MiB / 개별 이미지 등록 20MiB 제한도 유지합니다.

v0.4.2

Lua 편집기 인식을 위한 트리거 순서 조정

Lua가 있는 카드가 본체에서 다른 트리거 편집 모드로 열리는 상황을 줄이기 위해, 첫 효과가 triggerlua인 트리거를 앞에 배치하도록 했습니다.

  • Lua 추가·수정 적용, charx 가져오기와 모듈 출력에 Lua 우선 배치를 반영했습니다.
  • 여러 Lua를 하나의 코드로 합치지 않습니다. 개별 스크립트, 다른 트리거의 조건·효과는 유지합니다.
  • 본체 기본 Lua 편집기에는 첫 번째 Lua만 표시될 수 있습니다. BB의 Lua · 변수 탭에서는 여러 Lua 효과를 각각 편집할 수 있습니다.
트리거의 순서가 바뀌므로 실행 순서에 의존하는 복합 구성은 실제 호스트에서 확인해야 합니다. 카드에 Lua를 넣는 기능이며 BB가 Lua를 직접 실행하는 기능은 아닙니다.

v0.4.3

원문이 맞지 않는 문장은 사용자에게 구간 확인

일반 문장의 부분편집에서 원문이 일치하지 않거나 여러 곳에 일치하면, 즉시 적용하지 않고 수정 구간 확인 창을 엽니다.

  • 대상: 설명·첫 메시지·시작 상황의 본문, 로어북 content와 comment.
  • 중복된 정확 일치 구간, 공백·기호 차이, 유사 문장 후보를 보여 줍니다. 사용자가 실제 구간과 교체 내용을 비교해 선택합니다.
  • 후보가 적절하지 않으면 원문에서 구간을 직접 선택하거나, 교체 내용을 편집하거나, 해당 수정을 건너뛸 수 있습니다. 창 닫기·Escape도 해당 구간을 건너뜁니다.
  • 확인 창에서는 수정안만 준비합니다. 최종 반영은 기존 원고에 적용 버튼을 눌러야 합니다.
  • Lua·정규식 필드, 로어북 키, 변수 값은 기존의 정확 매칭을 유지합니다. 겹치는 구간은 거부하며 유사 후보를 자동 적용하지 않습니다.
  • 정확 매칭은 edits를 유지하고, 사용자 구간 확인을 거친 필드는 결과 문자열로 수정안에 저장합니다.

요청 중 편집 잠금·취소도 추가했습니다. LLM 요청과 응답 구간 검토 중에는 본문 편집을 잠그고, 완료·실패 후 잠금을 해제합니다. 요청 취소 후 늦게 도착한 응답은 폐기합니다. 실제 네트워크 요청 중단 여부는 호스트에 따라 다릅니다.

모바일에서 먼저 수정한 v0.4.2·v0.4.3 배포 JS의 변경을 유지보수 소스에 역반영했습니다. 이후 소스에서 다시 빌드해도 이 기능들이 유지됩니다.

v0.4.4

리스렐름 업데이트에서 대표 이미지가 안 보이던 문제 수정

BB가 대표 이미지를 assets/0.png에 저장하던 반면, 확인한 리스렐름 업로드 파서는 assets/icon/image로 시작하는 ZIP 항목을 대표 이미지로 선택했습니다.

  • 대표 이미지 경로를 assets/icon/image/main.png로 변경했습니다.
  • card.json의 icon / main 참조도 같은 파일을 가리키도록 맞췄습니다.
  • 이미지 바이트와 공유 에셋의 중복 제거는 유지합니다. 대표 이미지가 없는 카드를 추가 에셋으로 임의 대체하지 않습니다.
기존 charx는 다시 내보내야 합니다. 최신 BB를 설치하고 원고를 불러온 뒤 charx를 새로 내보내서 리스렐름 업데이트에 사용하세요. 실제 계정으로 업로드를 완료한 검증은 아직 수행하지 않았습니다.

v0.4.5

봇 아이콘 등록 · 교체 · 해제

에셋 목록 → 봇 아이콘 · 대표 이미지 메뉴를 추가했습니다. 기존 캐릭터 아이콘을 보존하는 것에 더해 BB 안에서 직접 등록·교체할 수 있습니다.

  • 20MiB 이하 이미지 파일을 등록하고, 이미 등록된 아이콘을 교체하거나 확인 후 해제할 수 있습니다.
  • 변경한 아이콘을 자동 저장·수동 임시 저장·복원과 charx 내보내기에 반영합니다.
  • 본체 반영은 캐릭터에 저장 / 새 캐릭터로 저장 버튼을 사용합니다. 본체에서 같은 아이콘이 별도로 바뀐 경우 저장 충돌을 검사합니다.
  • 아이콘 해제는 대표 이미지 참조와 관련 카드 메타데이터만 정리합니다. 공유 파일·감정 이미지·추가 에셋은 유지합니다.
  • 추가 에셋의 전체 삭제로 봇 아이콘이 삭제되지 않습니다. 파일 선택 취소·저장 실패·작업 대상 변경 시 기존 아이콘을 유지합니다.

업데이트할 때 알아둘 점

  • 배포 JS를 v0.4.5로 교체한 뒤 BB를 다시 열어 사용하세요. 설치 파일명과 플러그인 ID는 기존 risu_story_workshop를 유지합니다.
  • 기존 저장 사용자 프롬프트는 덮어쓰지 않습니다. 출력 형식 안내·예시는 기존 OUTPUT_FORMAT 치환 자리를 통해 전달합니다. 기본 문안까지 갱신하려면 해당 작업의 기본값 초기화를 사용하세요.
  • 기존 schemaVersion: 1 완성 문자열 응답과 이전 저장본을 계속 읽습니다. 부분편집은 응답 버전 2로 보냅니다. 저장본 외곽 버전은 1로 유지하며, 새 부분편집 수정안을 이전 BB에서 읽는 것은 보장하지 않습니다.
  • 자동 저장 주기는 기존 3분이며, 자동·수동 저장 슬롯은 각각 최근 1개를 유지합니다.
  • 본체 프리셋 자동 동기화, Lua 실행, HTML/CSS 미리보기를 새로 추가한 업데이트는 아닙니다.

포크 개발자용 변경 위치

  • src/text-edits.js: 정확 구간 매칭·겹침 검사·줄 번호 표시, 문장 후보 탐색과 사용자 선택 결과 조합.
  • src/core.js: 응답 버전 2 검증·수정 적용·Lua 우선 순서, 대표 이미지와 CCv3 참조의 저장·충돌 처리.
  • src/ui.js: 구간 확인창·편집 잠금·요청 취소, 에셋 다중 삭제, 봇 아이콘 등록·교체·해제.
  • src/charx.js: 출력 100MiB 제한 제거, Lua 순서 반영, 리스렐름 대표 이미지 경로.
  • tests/와 tools/verify-browser.mjs: 저장·복원·검증 실패·호스트 충돌·모바일 화면 회귀 검사.
