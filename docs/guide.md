# 사용 안내

봇빌더(BB)의 화면 구성과 기능을 설명합니다. 설치와 첫 흐름은 [README](../README.md)를, 프리셋·모듈은 [presets.md](presets.md)를, LLM 응답 형식과 부분편집은 [response-format.md](response-format.md)를, 지원 범위와 검증 상태는 [verification.md](verification.md)를 보세요.

## 화면 구성

- **상단 도구 줄**: 새 작업, 캐릭터 불러오기, charx 열기, 임시 저장, 저장본 불러오기, charx 내보내기, 캐릭터에 저장 / 새 캐릭터로 저장. 오른쪽 상태 문구는 원고 변경 여부와 마지막 자동 저장·임시 저장 시각을 보여 줍니다.
- **왼쪽 원고 구성**: 제작 노트, 캐릭터 설명, 로어북, 정규식, Lua · 변수, 첫 메시지, 에셋 목록, 프리셋. 불러온 캐릭터(새 작업이면 빈 원고)와 다른 내용이 있는 탭에는 점을 표시합니다. 로어북·정규식에는 항목 수를 표시합니다.
- **가운데 원고**: 선택한 탭의 본문을 직접 편집합니다. 각 탭 아래의 **LLM과 … 다듬기** 버튼은 해당 작업으로 요청 종류를 바꾸고 대화 창으로 이동합니다.
- **오른쪽 설계 대화**: 요청 종류·모델·요청 구성을 고르고 요청을 보냅니다. 입력창 위의 작업 표시줄이 지금 어떤 작업(설계 대화, 캐릭터 설명, 로어북 등)을 요청하는지와 그 작업이 바꾸는 범위를 보여 주고, 설계 대화가 아닌 요청과 답변에는 작업 태그가 붙습니다. 모바일에서는 요청 설정 버튼에 현재 작업 이름이, '대화 비우기' 왼쪽에 변경 범위 설명이 표시됩니다. 응답으로 만들어진 **원고 수정안**은 대화 아래에 카드로 쌓이며, **변경 내용 확인 → 원고에 적용**으로 채택합니다. 적용 직후에는 **적용 되돌리기**가 나타나고, 원고를 다시 편집하면 사라집니다.
- 탭 이동, 항목 선택, 모델 선택만으로는 작업이 시작되거나 자동 저장되지 않습니다. 원고·제작 노트·대화·요청문을 입력하면 작업이 시작됩니다.
- **모바일**: 상단 줄에 원고·대화 전환과 작업 메뉴(☰)가 있고, 제목 아래에 편집 상태와 자동·임시 저장 시각이 보입니다. 탭 바는 가로로 넘기며 가려진 탭이 있으면 오른쪽 끝이 흐려집니다. 수정안의 변경 내용은 기본으로 펼쳐져 있습니다.
- 긴 요청을 모바일에서 기다릴 때는 화면을 켜 두세요. 화면이 꺼지거나 다른 앱으로 전환하면 브라우저가 스트리밍 연결을 끊어 응답이 중간에 잘릴 수 있습니다. 요청 처리 중 상태 줄에 같은 안내가 표시됩니다.
- 오류 안내는 **닫기**를 누를 때까지 남아 있으며 본문을 선택해 복사할 수 있습니다. 일반 안내는 7초 뒤 사라집니다. 모바일에서는 안내가 상단에 표시됩니다.

## 포함한 기능

- 설정에서 시스템 설정 따르기 / 라이트 모드 / 무채색 다크 모드를 선택하고 저장합니다. 본문은 자체 배경으로 플러그인 프레임을 채우며, 창 크기에 맞춰 원고와 대화 영역의 스크롤을 분리합니다.
- 설계 대화, 제작 노트, 기존 원고를 참고하는 작업별 생성·수정 요청.
- 설명·성격·시나리오, 로어북, 정규식과 HTML/CSS 원문, Lua·초기 변수, 첫 메시지·대체 인사말, 이미지 에셋 목록 편집.
- 요청 버튼 옆의 **프롬프트**에서 전체 시스템·사용자 템플릿 확인, 편집·저장·기본값 초기화. 미저장 편집 내용은 전송에 사용하지 않습니다.
- 작업별 JSON 출력 구조와 올바른·잘못된 예시 제공. 응답의 OOC 제목·코드 펜스·앞뒤 설명은 제거하고 검증된 JSON 객체만 처리합니다.
- 요청 버튼을 누르면 별도 확인창 없이 전송합니다. 실제 전송 메시지는 프롬프트 창에서 선택적으로 확인할 수 있습니다. 작업 중 애니메이션·경과 시간, 대기 중단과 시간 초과를 지원하며 플러그인 자체의 자동 재시도는 없습니다.
- 내장 기본 프롬프트는 허구의 세계관, 인물의 동기·행동 일관성, 사건 결과, 개인정보와 참고자료·예시 해석을 안내합니다. 기존에 저장한 사용자 프롬프트는 유지하고, `기본값으로 초기화`하면 새 기본 문안을 불러옵니다.
- 미적용 제안과 원고의 분리. 원고가 변경되면 이전 제안을 적용하지 않습니다.
- 3분 자동 저장 최근 3개 + 수동 임시 저장 최근 1개. 대화·원고·완료된 제안·프롬프트 편집 초안을 함께 복원합니다.
- 최신 캐릭터에 변경 내용을 병합하고 대화·편집하지 않은 필드를 유지합니다. 충돌 시 원본·현재 리스·BB 원고를 비교하고 영역별로 저장할 쪽을 명시적으로 선택합니다. 검토 이후 원고나 본체가 다시 바뀌면 저장을 중단합니다.
- 정규식 매칭·캡처·치환 결과의 텍스트 검사. 생성한 HTML/CSS를 렌더링하거나 Lua를 실행하지 않습니다.
- CCv3 charx 읽기·쓰기, RisuAI 모듈의 로어북·정규식·트리거와 내장 이미지 에셋 처리.
- `.risup`·`.risupreset`·JSON 프롬프트 프리셋 가져오기, 블록 순서·역할·본문·v2 활성화 조건 편집, 토글 설정과 조립된 전송 내용 확인.
- 리스에 설치된 모듈 선택, 프리셋의 ID·namespace 참조 연결, 모듈 로어북·토글 적용 및 항목별 포함·제외 결과 확인.

## 저장과 복원

- 자동 저장은 3분 간격으로 동작하며 최근 3개(최근 · 1회 전 · 2회 전)를 보관합니다. 수동 **임시 저장**은 최근 1개를 보관합니다. 저장본에는 원고·제작 대화·미적용 수정안·프롬프트 편집 초안·요청 설정·프리셋 작업 상태가 함께 들어갑니다.
- **저장본 불러오기**에서 원하는 저장본을 고릅니다. 플러그인을 다시 열었을 때 저장본이 있으면 같은 창을 먼저 보여 줍니다. 복원해도 캐릭터 본체나 저장된 프롬프트 설정에는 자동으로 반영하지 않습니다.
- **캐릭터에 저장**은 불러온 뒤 바뀐 영역만 최신 캐릭터에 병합하고, 대화·편집하지 않은 필드는 유지합니다. 리스에서 같은 영역이 바뀌어 충돌하면 처음 불러온 내용·리스의 현재 내용·봇빌더 원고를 비교해 영역별로 저장할 쪽을 고릅니다. 검토 중에 원고나 본체가 다시 바뀌면 저장을 중단합니다.

## 요청 용량과 로어북 선택

- 전체 전송 문자 한도는 기본 3,000,000자, 설정 범위 1,000~10,000,000자이며 전체 전송 내용은 32MiB 이하입니다. 정확한 토큰 계수가 아니므로 실제 30만 토큰 입력은 모델·API의 컨텍스트와 응답 여유가 필요합니다. 본체 설정은 변경하지 않습니다.
- 이전 버전의 요청 한도는 최소 300만 자로 이관합니다. 현재 버전에서 직접 저장한 한도는 유지합니다. 기본 대기 시간은 900초이며, 이전 기본값 300초는 900초로 이관합니다.
- 로어북 탭에서 **이번 요청에 포함**을 항목별로 선택하거나 전체 포함/제외합니다. 직접·프리셋 요청에 함께 적용하며 원본 항목이나 항상 활성화 설정은 변경하지 않습니다. 이전 대화에 기록된 내용은 남고, 설치 모듈의 로어북은 모듈 탭에서 별도로 선택합니다.
- 선택 상태는 자동·수동 저장본에 포함됩니다. 모바일 목록은 세로 카드와 별도 스크롤을 사용하며 체크·편집 대상 선택 시 스크롤을 유지합니다. 75개 항목을 화면 폭 320·360·390·412·768px에서 검사했습니다.
- 로어북 응답은 새 항목과 실제 변경 필드만 반환하도록 안내합니다. 기존 항목은 ref로 찾아 병합하며 생략한 항목·필드는 보존합니다. 변경 검토에는 바뀐 항목·필드만 표시합니다. v0.4.0부터 본문 내부의 구간 수정도 before/after로 받고, 새 작성·전체 재작성에는 완성 문자열을 사용합니다.

## 원문 블록 · 코드를 JSON 밖으로

1.1.2부터 모델은 Lua·HTML·CSS·긴 본문을 JSON 문자열 대신 JSON 뒤의 `<<<이름>>>` … `<<</이름>>>` 블록으로 보낼 수 있습니다. 블록 안은 큰따옴표·줄바꿈·역슬래시를 그대로 쓰므로, 코드를 JSON에 넣다가 문법이 깨지는 오류가 크게 줄어듭니다. 사용자가 할 일은 없고, 응답 원문을 펼치면 블록이 그대로 보입니다. JSON 문법이 깨진 응답은 깨진 위치를 보여 주고 한 번 자동으로 다시 요청합니다.

## 분할 작업 · 긴 응답 나눠 받기

한 번에 쓰기에 너무 긴 결과(첫 메시지 HTML 콘솔, 긴 CSS, 로어북 여러 항목 등)는 모델 출력 상한이나 연결 끊김으로 중간에 잘리기 쉽습니다. 1.1.0부터는 봇빌더가 이런 작업을 구간으로 나눠 받습니다.

- 요청마다 **응답당 출력 예산**(기본 약 5,000토큰, 사고 토큰 제외)을 모델에 알려 줍니다. 예산 안에 끝나는 작업은 지금처럼 한 번에 옵니다.
- 결과가 예산을 넘을 것 같으면 모델은 첫 구간만 완성하고 남은 구간을 `plan`(구간 이름과 지시)으로 돌려줍니다. 봇빌더는 남은 구간을 순서대로 **자동으로 이어 요청**합니다. 작업 표시줄에 "캐릭터 설명 · 구간 2/5"처럼 진행이 보이고, 요청 취소로 언제든 멈출 수 있습니다.
- 구간 결과는 **임시 원고**에만 쌓입니다. 실제 원고는 끝까지 그대로이고, 모든 구간이 끝나면 **구간 묶음 하나의 수정안**이 대화 아래에 나타납니다. 변경 내용은 구간별로 표시되며 원고에 적용과 되돌리기는 한 번입니다.
- 중간에 취소하거나 한 구간이 실패하면 완성된 구간까지만 "(일부)" 수정안으로 남깁니다. 적용한 뒤 같은 요청을 다시 보내면 이어서 작성하게 할 수 있습니다.
- 응답이 중간에 끊기면 "더 작은 첫 구간만 쓰고 나머지는 plan으로" 지시를 붙여 **구간당 한 번 자동으로 다시 요청**합니다. 두 번째도 끊기면 그때까지의 구간만 남기고 오류를 안내합니다.
- **설정 → 분할 작업**에서 켜고 끌 수 있고, 출력 예산(1,000~30,000토큰)과 최대 구간 수(2~12, 기본 8)를 바꿀 수 있습니다. 구간마다 현재안 전체를 다시 보내므로 입력 토큰은 구간 수에 비례해 늘어납니다. 끄면 모델이 plan을 보내도 따라가지 않고 안내만 남깁니다.
- 프리셋 요청 모드에서도 같은 방식으로 동작합니다. 구간 요청에는 이미지를 다시 첨부하지 않습니다.

## 요청에 이미지 첨부

- 요청에 PNG·JPG·WEBP 이미지를 첨부하거나 클립보드에서 붙여넣을 수 있습니다. 요청당 최대 4장, 장당 5MiB, 합계 12MiB, 이미지당 4천만 픽셀 이하입니다. 이미지 입력을 지원하는 모델이 필요합니다.
- 첨부는 요청 작업별로 관리합니다. 직접·프리셋 조립 후 마지막 사용자 메시지에 넣고, 이미지 데이터도 전체 32MiB 전송 제한에 포함합니다. 이미지 내용의 토큰 수는 계산하지 않습니다.
- 전송을 시작하면 첨부를 비우고 대화 기록으로 옮깁니다. 이전 이미지는 자동 재전송하지 않으며 **이미지 다시 첨부**로 재사용합니다.

## 에셋 목록과 봇 아이콘

- 에셋 목록 상단의 **봇 아이콘 · 대표 이미지**에서 이미지 파일을 등록·교체·해제합니다. 개별 이미지 한도는 20MiB입니다. 변경한 아이콘은 저장본·charx 내보내기에 반영하며, 본체에는 저장 버튼으로 반영합니다.
- 추가 에셋은 체크박스로 여러 항목을 골라 선택 삭제·전체 삭제할 수 있습니다. 삭제는 현재 원고의 참조만 제거하며 대표 이미지·감정 이미지·공유 파일은 유지합니다. charx에서 가져온 에셋의 카드 참조도 함께 정리합니다.
- charx 내보내기에는 에셋 합계 상한이 없습니다. 브라우저 메모리와 ZIP 형식의 한계는 적용됩니다. 대표 이미지는 RisuRealm 썸네일 규칙에 맞춰 `assets/icon/image/` 아래에 기록합니다.

## Dusk Atelier 연동

봇빌더 1.0.4부터 Dusk Atelier 플러그인과 DA Interop v1 규약으로 연결됩니다. 두 플러그인이 공유하는 리스의 플러그인 저장소에 작은 JSON 항목을 주고받는 방식이라 본체나 다른 플러그인의 코드를 건드리지 않습니다.

- **Dusk가 부탁할 수 있는 일은 두 가지**입니다. `open`은 메뉴에서 봇빌더를 누른 것과 똑같이 화면을 열고, `draft`는 지금 작업 중인 원고를 읽어 줍니다. 원고를 고치거나 저장하거나 지우는 요청은 없으며, 봇빌더는 그런 요청을 받아도 `unknown action`으로 거절합니다.
- `draft`로 넘기는 내용은 이름, 편집 중인 캐릭터 ID(새 원고면 null), 작업 시작·변경 여부, 마지막 자동 저장 시각, 편집 가능한 필드만 담은 원고입니다. 채팅 기록과 내부 ID는 포함하지 않습니다. 결과는 1MiB 이하여야 하며 넘으면 오류로 응답합니다.
- 요청은 화면이 보일 때 1초마다 확인하고, 15초가 지난 요청이나 봇빌더를 켰을 때 남아 있던 오래된 요청은 실행하지 않습니다. 그래서 나중에 봇빌더를 켰을 때 창이 갑자기 열리는 일은 없습니다. 같은 요청은 한 번만 처리합니다.
- 저장소 키는 `da_interop:reg:risu-story-workshop`(봇빌더가 기록), `da_interop:action:risu-story-workshop`(Dusk가 기록)입니다. 봇빌더는 Dusk에 설정 항목을 등록하지 않으므로 설정 동기화 키는 쓰지 않습니다. 구현은 `src/interop.js`에 있고, 규약 원문은 https://github.com/Pyser08/dusk-atelier-interop 입니다.
- Dusk를 쓰지 않으면 등록 키 하나가 기록되는 것 외에 아무 변화가 없습니다. 연동이 실패해도 봇빌더는 평소처럼 동작하며 콘솔에만 경고를 남깁니다.

## 정규식 테스트

정규식 테스트는 RE2JS 공통 문법을 사용합니다. 역참조·전방 탐색, 지원하지 않는 플래그는 테스트를 거부하고 원고 편집은 유지합니다. CBS·실제 채팅 상태를 실행하지 않으므로 `{{data}}` 등 매크로는 문자 그대로 표시될 수 있습니다. 패턴 1,024자 / 입력 65,536자 / 매칭 1,000개 / 출력 1MiB 한도를 표시합니다.

## charx 입출력

charx 입력은 100MiB, 압축 해제는 200MiB 이하입니다. 별도 모듈 에셋과 지원하지 않는 URI 형식은 오류를 표시합니다. HTTP(S)·ccdefault:·파일이 없는 embeded:// 참조는 메타데이터로 보존하며 외부에서 자동 다운로드하지 않습니다. 내보낼 때 해당 참조를 안내하고, 원본 내장 파일을 확보하지 못한 항목은 이미지 표시를 보장하지 않습니다. 카드 가져오기로 저수준 실행 권한을 자동 허용하지 않습니다. CHARX 저장 시 Lua 트리거를 맨 앞에 배치해 리스가 Lua 편집기로 인식하게 하며, 다른 트리거와 개별 Lua 코드는 모두 보존합니다.
