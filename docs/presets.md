# 프롬프트 프리셋과 설치 모듈

## 가져온 프롬프트 프리셋 사용

1. 본체에서 프리셋을 파일로 내보낸 뒤 공방의 **프롬프트 프리셋 → 프리셋 가져오기**에서 선택합니다. 가져오면 요청 구성이 **프리셋 요청**으로 바뀝니다.
2. **프롬프트 블록**에서 본문·역할·순서·사용 여부와 v2 조건을 편집합니다. 제작 대화 블록에는 현재 공방 요청이 정확히 한 번 포함되도록 범위를 설정합니다. `0 → end`는 전체 제작 대화와 이번 요청입니다.
3. **토글 설정**에서 스위치·선택형·텍스트·여러 줄 값을 정합니다. 선택형 토글의 CBS 값은 본체처럼 0부터 시작하는 번호입니다. **참고자료**에서 사용자 이름·페르소나·작가 노트·메모리와 추가 전역 변수를 입력할 수 있습니다.
4. **전송 내용**에서 포함·제외된 블록, 오류와 역할별 전체 메시지를 확인하고 기존 요청 버튼으로 전송합니다. 작업 지침·현재안·출력 형식을 포함한 공방 요청을 제작 대화 블록의 사용자 메시지 자리에 넣고, 이전 제작 대화는 채팅 블록의 범위를 따릅니다. 요청 옆 **프롬프트**에서도 실제 조립 결과를 볼 수 있습니다.
5. **프리셋 설정 저장**으로 편집본·선택 모듈·토글·요청 구성을 플러그인 저장소에 보관합니다. 자동 저장·수동 임시 저장에도 작업 당시 프리셋과 선택 모듈을 포함합니다. **JSON 내보내기**는 비활성 블록을 제외한 프롬프트 사본이며, 공방 토글 선택값·참고자료·모듈 사본은 포함하지 않습니다. 원문·고급 JSON 편집은 해당 **적용** 버튼을 눌러야 반영됩니다.

본체 코드는 변경하지 않으며, 빈 캐릭터나 본체 채팅을 통한 요청 가로채기는 사용하지 않습니다. 가져온 사본과 토글 값은 공방 안에서 관리합니다. 본체의 현재 프리셋·토글과 자동 동기화하지 않고, 파일의 모델·API 키·접속 설정도 가져오지 않습니다. 실행 모델은 기존 **메인 모델 / 보조 모델** 선택을 따릅니다. **직접 요청**으로 바꾸면 기존 동작을 사용합니다.

지원 범위는 다음과 같습니다. 본체의 전체 프롬프트 엔진과 동일한 결과를 보장하는 이식은 아닙니다.

| 항목 | 공방 처리 |
| --- | --- |
| 파일 | `.risup`의 RPack·압축·MessagePack·AES-GCM, `.risupreset`, UTF-8 JSON. 입력·압축 해제 각각 32MiB 이하, 블록 500개 이하 |
| 블록 | 일반·구형 추가 프롬프트·CoT, ChatML, 대화 범위, 설명·페르소나·작가 노트·로어북·메모리 입력·마지막 지시, assistant prefill, 캐시 지점. 구형 활성화 플래그가 있으면 유지 |
| v2 | 조건 추가·삭제, AND/OR, 같음·다름·대소 비교, 토글 그룹·설명·구분선 |
| CBS | `char`, `user`, `description`, `personality`, `scenario`, `persona`, `firstmessage`/`first_message`, `systemprompt`, `lorebook`, `chatindex`, `lastusermessage`, `lastcharmessage`, `original`, `slot`; `getglobalvar`, `getvar`, 비교·논리 함수, `#if`/`#if_pure`/`#when`, `:else`/else, 주석, trim·lower·upper, `{{? 계산식}}`·`{{calc::계산식}}`, `moduleenabled`/`module_enabled`·`moduleassetlist`/`module_assetlist` |
| 자료 연결 | 설명은 공방 현재안, 대화는 공방 제작 대화. 로어북은 현재안에서 체크한 항목과 선택 모듈의 포함 항목을 넣고 본체의 키워드 활성화·검색·토큰 예산은 실행하지 않음. 페르소나·작가 노트·메모리는 공방 입력값 |
| 별도 처리 | 미선택 모듈 참조는 선택하거나 전체 제외해야 함. 입력·전처리 정규식, 시작·입력·요청 트리거, Lua·JS 콜백·MCP는 미지원이며 명시적 제외 전까지 전송을 막음. 출력·표시 정규식, 배경 코드, 일반 수동·표시·출력 트리거는 BB 단계에 적용하지 않음. 보조 오버레이·미지원 CBS·@@ 지시도 별도 처리 필요 |

v0.2.1에서는 리스처럼 닫는 태그가 가장 가까운 CBS 블록을 닫습니다. `{{#if_pure …}}…{{/if}}`와 `{{/}}`도 허용합니다. 조건식은 `1`·`true`만 참으로 처리하며 `#if`의 들여쓰기 제거와 `#if_pure`의 공백 보존을 구분합니다. `#when`은 비교·AND/OR·NOT·var/toggle·vis/tis 연산과 keep/legacy 모드를 처리합니다. 계산식의 산술·비교·논리·괄호·`$지역변수`·`@전역변수`는 확인한 RisuBard RPN 계산 방식에 맞추되 공방 값만 읽습니다. 식 길이 65,536자·괄호 중첩 49단계 한도를 적용하며 JavaScript를 실행하지 않습니다.

캐시 블록은 앞선 메시지 중 대상 역할과 깊이에 맞는 항목에 `cachePoint: true`를 붙입니다. 전송 내용에서 표식을 확인할 수 있으며, 새로운 프롬프트 텍스트는 만들지 않습니다. 실제 캐시 사용과 과금은 본체·제공자 설정을 따르며 실서비스 동작은 별도 검증이 필요합니다.

CBS는 지원 목록만 해석하며 코드 실행·본체 변수 변경은 제공하지 않습니다. 원고·사용자 요청·토글 입력값을 다시 CBS로 해석하지 않습니다. 감싸는 서식은 `{{slot}}`을 포함해야 합니다. 로어북·메모리·마지막 지시의 감싸는 서식도 공방 자료에 적용하는 자체 어댑터입니다. 본체의 첫 인사·예시 대화·새 채팅 표시는 제작 대화에 자동 삽입하지 않으며, `trimStartNewChat`·`maxThoughtTagDepth` 같은 해당 본체 전용 처리는 적용하지 않습니다. `sendChatAsSystem`·`sendName`·`utilOverride`·`customChainOfThought`가 활성화된 파일은 미지원 옵션을 표시하고 전송을 중단합니다. 입력은 기존 문자 수 한도를 그대로 적용하며 자동 토큰 절삭을 하지 않습니다.

`user_input`은 대조한 공식 CBS에 정의된 변수가 아닙니다. BB에서는 리스의 미정의 표기 처리처럼 원문으로 취급하고 안내를 표시하며, 현재 요청문에 매핑하지 않습니다. 사용자가 제공한 `{{#if {{user_input}}}} … {{/if}}`는 참 값 `1`·`true`가 아니므로 블록 전체가 빠집니다. 실제 요청은 기존 제작 대화 블록으로 한 번 전달합니다. 이 예외가 다른 미지원 CBS 함수를 실행하거나 무시한다는 뜻은 아닙니다.

## 설치 모듈 선택

1. **프롬프트 프리셋 → 설치 모듈 선택**을 누릅니다. 공식 `getDatabase(['modules'])`로 설치 목록만 읽습니다. 호스트가 데이터 접근 권한을 물으면 허용해야 목록을 볼 수 있습니다. 모듈 파일 가져오기는 제공하지 않습니다.
2. 이름·ID·namespace로 검색하거나 **프리셋 참조 모듈 선택**으로 일치하는 모듈을 고른 뒤 **선택 모듈 적용**을 누릅니다. ID 중복은 제거하고 본체 목록의 순서를 유지합니다. ID 또는 namespace로 참조를 해결하며, 설치되지 않았거나 선택하지 않은 참조는 전송 전에 표시합니다.
3. **모듈** 탭에서 로어북 원문과 포함 여부를 확인합니다. 로어북은 전체 제작 자료로 처리하므로 본체의 자동 활성화와 다릅니다. 모듈 로어북 안의 지원 CBS는 공방의 현재안·토글로 한 번 해석합니다. `@@` 위치·활성화 지시와 해석하지 못하는 CBS가 있는 항목은 기본적으로 전송을 막으므로 제외하거나, 모듈별 **해석 못 하는 조건은 거짓으로 보고 본문만 포함**을 켭니다. 켜면 `@@` 줄은 빼고 해석 못 하는 조건은 거짓 분기, 해석 못 하는 표기는 빈 값으로 처리해 본문을 살려 넣으며, 전송 내용의 모듈별 결과에 `relaxed`로 표시됩니다.
4. **정규식·트리거 처리 내역과 원문 확인**에서 유형·이름·코드와 처리 이유를 확인합니다. 입력(`editinput`)·전처리(`editprocess`) 정규식, 시작·입력·요청 트리거, Lua·JS 콜백, 모듈 JS·MCP는 아직 지원하지 않아 전송을 막습니다. **이 모듈의 요청 관련 미지원 처리를 제외**를 직접 선택하면 해당 처리를 생략할 수 있습니다. Lua·JS 코드 트리거는 수동·표시·출력으로 지정돼 있어도 여러 콜백을 등록할 수 있어 일괄적으로 무관하다고 처리하지 않습니다.
5. **토글 설정**에는 프리셋과 선택 모듈의 정의를 합쳐 표시합니다. 같은 키·형식·선택지는 한 값으로 공유하고 형식이 다르면 충돌을 표시합니다. 본체의 현재 토글 값은 복사하지 않으며 공방에서 값을 정합니다. 로어북 블록 또는 `{{lorebook}}`이 있는 블록에서 모듈 자료를 사용합니다. 포함할 위치가 없으면 전송을 중단합니다.
6. **전송 내용 → 모듈별 포함·제외 결과**에서 실제 반영 여부를 확인합니다. 이 화면은 현재의 직접 요청·프리셋 요청 모드를 따릅니다. 직접 요청 모드에는 모듈을 적용하지 않습니다. `moduleenabled`는 선택 모듈의 namespace를 조회하고 `moduleassetlist`는 에셋 이름 목록만 반환하며 파일을 읽거나 렌더링하지 않습니다.

출력(`editoutput`)·표시(`editdisplay`) 정규식은 리스 채팅 응답·화면의 후처리이므로 BB의 구조화된 JSON 응답과 수정안에 적용하지 않고 전송도 막지 않습니다. 배경 코드와 일반 수동·표시·출력 트리거도 BB에서 실행하지 않으며 내역에 `not-applicable`로 기록합니다. 빈 IN 정규식도 네이티브처럼 실행하지 않습니다. 프리셋에 들어 있는 정규식도 같은 기준으로 분류하며 **참고자료 → 프리셋 정규식 처리 내역과 원문 확인**, **전송 내용 → 프리셋 정규식 처리 결과**에서 볼 수 있습니다. 규칙 유형을 확인할 수 없으면 차단을 유지합니다. 기존에 저장한 명시적 제외 설정은 유지합니다.

선택 모듈은 공방 안의 사본으로 저장합니다. 본체의 모듈 활성화·캐릭터·모듈 내용은 변경하지 않습니다. 본체에서 수정한 모듈은 선택창을 다시 열어 적용하면 갱신되며, 내용이 바뀌면 해당 모듈의 제외 설정을 초기화해 다시 검토하게 합니다. 프리셋을 새로 가져와도 선택 모듈과 모듈 토글 값은 유지합니다. 모듈 선택은 최대 100개·데이터 합계 32MiB·로어북 합계 3,000개이며 프리셋과 합친 토글은 최대 300개입니다. 기존 요청 문자 수 상한도 적용합니다.
