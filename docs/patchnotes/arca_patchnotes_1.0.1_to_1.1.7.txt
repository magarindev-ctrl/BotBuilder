<div style="padding:20px;margin-bottom:16px;border:1px solid #d6dad4;border-radius:12px;background:#ffffff;"><p style="margin:0 0 4px;color:#5c6a65;font-size:13px;">v1.1.2 · v1.1.6</p><h2 style="margin:0 0 12px;color:#22302c;font-size:20px;line-height:1.5;">코드와 긴 본문은 원문 블록으로 받습니다</h2><p style="margin:0 0 10px;">Lua·HTML·CSS·정규식을 JSON 문자열에 넣으면 큰따옴표와 줄바꿈 이스케이프에서 자주 깨졌습니다. 이제 모델은 그런 값을 JSON 뒤에 <code>&lt;&lt;&lt;이름&gt;&gt;&gt;</code> … <code>&lt;&lt;&lt;/이름&gt;&gt;&gt;</code> 블록으로 보내고, 봇빌더가 제자리에 끼워 넣습니다.</p><ul style="margin:0 0 12px;padding-left:22px;"><li>사용자가 할 일은 없습니다. 출력 형식 안내에 포함되므로 저장해 둔 프롬프트에서도 바로 동작합니다.</li><li>모델이 참조 형식을 틀려도(블록은 보냈는데 JSON에서 안 가리키거나, 없는 블록을 가리키는 경우) 올바른 형식을 짚어 <strong>한 번 자동으로 다시 요청</strong>합니다. 태그 모양 그대로 적은 참조는 그냥 받아들입니다.</li></ul></div>

<div style="padding:20px;margin-bottom:16px;border:1px solid #d6dad4;border-radius:12px;background:#ffffff;"><p style="margin:0 0 4px;color:#5c6a65;font-size:13px;">v1.0.2 · v1.1.1 · v1.1.2 · v1.1.7</p><h2 style="margin:0 0 12px;color:#22302c;font-size:20px;line-height:1.5;">응답이 깨지면 이유를 알려 줍니다</h2><ul style="margin:0 0 12px;padding-left:22px;"><li><strong>JSON 문법 오류</strong>는 "완성된 JSON 응답 객체를 찾지 못했습니다" 대신 <strong>깨진 위치와 앞뒤 원문</strong>을 보여 주고, 그 자리를 알려 주는 지시를 붙여 한 번 자동으로 다시 요청합니다.</li><li>바깥 JSON이 깨졌을 때 안쪽 조각을 응답으로 오인해 "필수 필드 누락: schemaVersion"이 나오던 오진을 고쳤습니다.</li><li>설계 대화 응답에 <code>"choices": []</code>처럼 <strong>빈 필드</strong>가 섞여 와도 제안을 버리지 않습니다. 내용이 있는 엉뚱한 필드만 거부합니다.</li><li>Lua 초기 변수에 객체·배열이 오면 "값은 한 줄 문자열이어야 합니다"로 바로 안내합니다. 리스의 초기 변수는 <code>키=값</code> 한 줄이라 여러 값은 변수를 나눠야 합니다.</li></ul></div>

<div style="padding:20px;margin-bottom:16px;border:1px solid #d6dad4;border-radius:12px;background:#ffffff;"><p style="margin:0 0 4px;color:#5c6a65;font-size:13px;">v1.1.4</p><h2 style="margin:0 0 12px;color:#22302c;font-size:20px;line-height:1.5;">첫 메시지 CBS 검사</h2><p style="margin:0 0 10px;">모델이 조건문의 else를 <code>{{else}}</code>로 쓰면 리스는 글자 그대로 보여 주고 분기가 깨집니다. 리스 CBS의 else는 <code>{{:else}}</code>입니다.</p><ul style="margin:0 0 12px;padding-left:22px;"><li>수정안 검토 제목에 <strong>"CBS 경고 N건"</strong>이 붙고, 구간별로 어떤 표기가 문제인지 알려 줍니다. 미지원 else 표기와 <code>{{#if}}</code>/<code>{{/if}}</code> 짝 불일치를 봅니다. 적용을 막지는 않습니다.</li><li>경고가 뜨면 "{{else}}를 {{:else}}로 바꿔 줘"라고 부분편집을 요청하면 됩니다. 프롬프트에도 올바른 CBS 문법을 넣어 같은 실수가 줄어듭니다.</li></ul></div>
