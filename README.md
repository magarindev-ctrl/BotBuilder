# 봇빌더 (BB)

LLM과 대화하며 RisuBard용 캐릭터·시뮬레이션을 만들어 가는 API v3 플러그인입니다. PC에서는 원고와 제작 대화를 나란히 봅니다.

## 설치와 시작

1. RisuBard의 설정 → 플러그인에서 **`dist/risu_story_workshop.js`**를 추가합니다. 이 파일 하나에 모든 실행 코드가 들어 있습니다.
2. 플러그인 설정 항목 또는 햄버거 메뉴의 **봇빌더**를 엽니다.
3. 새 작업을 시작하거나 기존 캐릭터·charx를 불러옵니다.
4. 제작 노트에 방향을 적고, 오른쪽 **설계 대화 → 함께 구상하기**로 LLM과 의논합니다. 모델과 접속 정보는 RisuBard의 메인·보조 모델 설정을 따릅니다.
5. 설명·로어북·정규식·Lua·첫 메시지 요청으로 구체화합니다. **변경 내용 확인 → 원고에 적용**으로 수정안을 채택합니다.
6. **캐릭터에 저장 / 새 캐릭터로 저장** 또는 **charx 내보내기**로 결과를 저장합니다.

## 플러그인 업데이트

- [최신 배포 JS](https://raw.githubusercontent.com/magarindev-ctrl/BotBuilder/main/dist/risu_story_workshop.js)를 업데이트 주소로 등록했습니다. 다음 배포에서 버전이 올라가면 리스의 플러그인 업데이트 버튼으로 교체할 수 있습니다. 자동으로 설치되는 방식은 아닙니다.
- 업데이트 주소가 없는 기존 설치본은 이 JS 파일을 한 번 직접 가져와 기존 플러그인을 교체해야 합니다. 이번 변경은 버전을 **1.0.0으로 유지**하므로 이전 1.0.0에 새 업데이트 알림이 생기지는 않습니다.
- 빌드 시 주소가 헤더에 포함됩니다. 이후 배포에서도 내부 이름 `risu_story_workshop`과 이 주소를 유지하고 버전을 올려 배포합니다.

## 포함한 기능

- 설정에서 시스템 설정 따르기 / 라이트 모드 / 무채색 다크 모드를 선택하고 저장합니다. 본문은 자체 배경으로 플러그인 프레임을 채우며, 창 크기에 맞춰 원고와 대화 영역의 스크롤을 분리합니다.
- 설계 대화, 제작 노트, 기존 원고를 참고하는 작업별 생성·수정 요청.
- 설명·성격·시나리오, 로어북, 정규식과 HTML/CSS 원문, Lua·초기 변수, 첫 메시지·대체 인사말, 이미지 에셋 목록 편집.
- 요청 버튼 옆의 **프롬프트**에서 전체 시스템·사용자 템플릿 확인, 편집·저장·기본값 초기화. 미저장 편집 내용은 전송에 사용하지 않습니다.
- 작업별 JSON 출력 구조와 올바른·잘못된 예시 제공. 응답의 OOC 제목·코드 펜스·앞뒤 설명은 제거하고 검증된 JSON 객체만 처리합니다.
- 요청 버튼을 누르면 별도 확인창 없이 전송합니다. 실제 전송 메시지는 프롬프트 창에서 선택적으로 확인할 수 있습니다. 작업 중 애니메이션·경과 시간, 대기 중단과 시간 초과를 지원하며 플러그인 자체의 자동 재시도는 없습니다.
- 내장 기본 프롬프트는 허구의 세계관, 인물의 동기·행동 일관성, 사건 결과, 개인정보와 참고자료·예시 해석을 안내합니다. 기존에 저장한 사용자 프롬프트는 유지하고, `기본값으로 초기화`하면 새 기본 문안을 불러옵니다.
- 미적용 제안과 원고의 분리. 원고가 변경되면 이전 제안을 적용하지 않습니다.
- 3분 자동 저장 최근 1개 + 수동 임시 저장 최근 1개. 대화·원고·완료된 제안·프롬프트 편집 초안을 함께 복원합니다.
- 최신 캐릭터에 변경 내용을 병합하고 대화·편집하지 않은 필드를 유지합니다. 충돌 시 원본·현재 리스·BB 원고를 비교하고 영역별로 저장할 쪽을 명시적으로 선택합니다. 검토 이후 원고나 본체가 다시 바뀌면 저장을 중단합니다.
- 정규식 매칭·캡처·치환 결과의 텍스트 검사. 생성한 HTML/CSS를 렌더링하거나 Lua를 실행하지 않습니다.
- CCv3 charx 읽기·쓰기, RisuAI 모듈의 로어북·정규식·트리거와 내장 이미지 에셋 처리.
- `.risup`·`.risupreset`·JSON 프롬프트 프리셋 가져오기, 블록 순서·역할·본문·v2 활성화 조건 편집, 토글 설정과 조립된 전송 내용 확인.
- 리스에 설치된 모듈 선택, 프리셋의 ID·namespace 참조 연결, 모듈 로어북·토글 적용 및 항목별 포함·제외 결과 확인.

## 요청 용량과 로어북 선택

- 전체 전송 문자 한도는 기본 3,000,000자, 설정 범위 1,000~10,000,000자이며 전체 전송 내용은 32MiB 이하입니다. 정확한 토큰 계수가 아니므로 실제 30만 토큰 입력은 모델·API의 컨텍스트와 응답 여유가 필요합니다. 본체 설정은 변경하지 않습니다.
- 이전 버전의 요청 한도는 최소 300만 자로 이관합니다. 현재 버전에서 직접 저장한 한도는 유지합니다. 기본 대기 시간은 900초이며, 이전 기본값 300초는 900초로 이관합니다.
- 로어북 탭에서 **이번 요청에 포함**을 항목별로 선택하거나 전체 포함/제외합니다. 직접·프리셋 요청에 함께 적용하며 원본 항목이나 항상 활성화 설정은 변경하지 않습니다. 이전 대화에 기록된 내용은 남고, 설치 모듈의 로어북은 모듈 탭에서 별도로 선택합니다.
- 선택 상태는 자동·수동 저장본에 포함됩니다. 모바일 목록은 세로 카드와 별도 스크롤을 사용하며 체크·편집 대상 선택 시 스크롤을 유지합니다. 75개 항목을 화면 폭 320·360·390·412·768px에서 검사했습니다.
- 로어북 응답은 새 항목과 실제 변경 필드만 반환하도록 안내합니다. 기존 항목은 ref로 찾아 병합하며 생략한 항목·필드는 보존합니다. 변경 검토에는 바뀐 항목·필드만 표시합니다. v0.4.0부터 본문 내부의 구간 수정도 before/after로 받고, 새 작성·전체 재작성에는 완성 문자열을 사용합니다.

## 소스와 배포 파일

v0.3.3~v0.3.5에서 배포 JS에 직접 적용된 용량 확대·모바일 목록·로어북 부분 수정 변경을 소스로 동기화했습니다. v0.3.6은 JSON 형식·예시 표시를 복원하고, 설명이나 코드 펜스로 둘러싼 배열 응답도 거부합니다. 저장한 프롬프트와 프리셋 프리필은 유지합니다.

수정은 src/에서 하고 npm run build로 dist/risu_story_workshop.js를 생성합니다. 빌드 헤더 버전은 package.json에서 가져오며 런타임 버전과 다르면 빌드를 중단합니다. 재배포에는 같은 버전의 소스·빌드 파일·라이선스를 함께 제공하세요.

## 가져온 프롬프트 프리셋 사용

1. 본체에서 프리셋을 파일로 내보낸 뒤 공방의 **프롬프트 프리셋 → 프리셋 가져오기**에서 선택합니다. 가져오면 요청 구성이 **프리셋 요청**으로 바뀝니다.
2. **프롬프트 블록**에서 본문·역할·순서·사용 여부와 v2 조건을 편집합니다. 제작 대화 블록에는 현재 공방 요청이 정확히 한 번 포함되도록 범위를 설정합니다. `0 → end`는 전체 제작 대화와 이번 요청입니다.
3. **토글 설정**에서 스위치·선택형·텍스트·여러 줄 값을 정합니다. 선택형 토글의 CBS 값은 본체처럼 0부터 시작하는 번호입니다. **참고자료**에서 사용자 이름·페르소나·작가 노트·메모리와 추가 전역 변수를 입력할 수 있습니다.
4. **전송 내용**에서 포함·제외된 블록, 오류와 역할별 전체 메시지를 확인하고 기존 요청 버튼으로 전송합니다. 작업 지침·현재안·출력 형식을 포함한 공방 요청을 제작 대화 블록의 사용자 메시지 자리에 넣고, 이전 제작 대화는 채팅 블록의 범위를 따릅니다. 요청 옆 **프롬프트**에서도 실제 조립 결과를 볼 수 있습니다.
5. **프리셋 설정 저장**으로 편집본·선택 모듈·토글·요청 구성을 플러그인 저장소에 보관합니다. 자동 저장·수동 임시 저장에도 작업 당시 프리셋과 선택 모듈을 포함합니다. **JSON 내보내기**는 비활성 블록을 제외한 프롬프트 사본이며, 공방 토글 선택값·참고자료·모듈 사본은 포함하지 않습니다. 원문·고급 JSON 편집은 해당 **적용** 버튼을 눌러야 반영됩니다.

본체 코드는 변경하지 않으며, 빈 캐릭터나 본체 채팅을 통한 요청 가로채기는 사용하지 않습니다. 가져온 사본과 토글 값은 공방 안에서 관리합니다. 본체의 현재 프리셋·토글과 자동 동기화하지 않고, 파일의 모델·API 키·접속 설정도 가져오지 않습니다. 실행 모델은 기존 **메인 모델 / 보조 모델** 선택을 따릅니다. **직접 요청**으로 바꾸면 기존 동작을 사용합니다.

지원 범위는 다음과 같습니다. 본체의 전체 프롬프트 엔진과 동일한 결과를 보장하는 이식은 아닙니다.

| 항목 | 공방 처리 |
| --- | --- |
| 파일 | `.risup`의 RPack·압축·MessagePack·AES-GCM, `.risupreset`, UTF-8 JSON. 입력·압축 해제 각각 32MiB 이하, 블록 500개 이하 |
| 블록 | 일반·구형 추가 프롬프트·CoT, ChatML, 대화 범위, 설명·페르소나·작가 노트·로어북·메모리 입력·마지막 지시, assistant prefill, 캐시 지점. 구형 활성화 플래그가 있으면 유지 |

v0.2.1에서는 리스처럼 닫는 태그가 가장 가까운 CBS 블록을 닫습니다. `{{#if_pure …}}…{{/if}}`와 `{{/}}`도 허용합니다. 조건식은 `1`·`true`만 참으로 처리하며 `#if`의 들여쓰기 제거와 `#if_pure`의 공백 보존을 구분합니다. `#when`은 비교·AND/OR·NOT·var/toggle·vis/tis 연산과 keep/legacy 모드를 처리합니다. 계산식의 산술·비교·논리·괄호·`$지역변수`·`@전역변수`는 확인한 RisuBard RPN 계산 방식에 맞추되 공방 값만 읽습니다. 식 길이 65,536자·괄호 중첩 49단계 한도를 적용하며 JavaScript를 실행하지 않습니다.

캐시 블록은 앞선 메시지 중 대상 역할과 깊이에 맞는 항목에 `cachePoint: true`를 붙입니다. 전송 내용에서 표식을 확인할 수 있으며, 새로운 프롬프트 텍스트는 만들지 않습니다. 실제 캐시 사용과 과금은 본체·제공자 설정을 따르며 실서비스 동작은 별도 검증이 필요합니다.

CBS는 지원 목록만 해석하며 코드 실행·본체 변수 변경은 제공하지 않습니다. 원고·사용자 요청·토글 입력값을 다시 CBS로 해석하지 않습니다. 감싸는 서식은 `{{slot}}`을 포함해야 합니다. 로어북·메모리·마지막 지시의 감싸는 서식도 공방 자료에 적용하는 자체 어댑터입니다. 본체의 첫 인사·예시 대화·새 채팅 표시는 제작 대화에 자동 삽입하지 않으며, `trimStartNewChat`·`maxThoughtTagDepth` 같은 해당 본체 전용 처리는 적용하지 않습니다. `sendChatAsSystem`·`sendName`·`utilOverride`·`customChainOfThought`가 활성화된 파일은 미지원 옵션을 표시하고 전송을 중단합니다. 입력은 기존 문자 수 한도를 그대로 적용하며 자동 토큰 절삭을 하지 않습니다.

`user_input`은 대조한 공식 CBS에 정의된 변수가 아닙니다. BB에서는 리스의 미정의 표기 처리처럼 원문으로 취급하고 안내를 표시하며, 현재 요청문에 매핑하지 않습니다. 사용자가 제공한 `{{#if {{user_input}}}} … {{/if}}`는 참 값 `1`·`true`가 아니므로 블록 전체가 빠집니다. 실제 요청은 기존 제작 대화 블록으로 한 번 전달합니다. 이 예외가 다른 미지원 CBS 함수를 실행하거나 무시한다는 뜻은 아닙니다.

## 설치 모듈 선택

1. **프롬프트 프리셋 → 설치 모듈 선택**을 누릅니다. 공식 `getDatabase(['modules'])`로 설치 목록만 읽습니다. 호스트가 데이터 접근 권한을 물으면 허용해야 목록을 볼 수 있습니다. 모듈 파일 가져오기는 제공하지 않습니다.
2. 이름·ID·namespace로 검색하거나 **프리셋 참조 모듈 선택**으로 일치하는 모듈을 고른 뒤 **선택 모듈 적용**을 누릅니다. ID 중복은 제거하고 본체 목록의 순서를 유지합니다. ID 또는 namespace로 참조를 해결하며, 설치되지 않았거나 선택하지 않은 참조는 전송 전에 표시합니다.
3. **모듈** 탭에서 로어북 원문과 포함 여부를 확인합니다. 로어북은 전체 제작 자료로 처리하므로 본체의 자동 활성화와 다릅니다. 모듈 로어북 안의 지원 CBS는 공방의 현재안·토글로 한 번 해석합니다. `@@` 위치·활성화 지시는 처리하지 않으며 해당 항목을 제외해야 합니다.
4. **정규식·트리거 처리 내역과 원문 확인**에서 유형·이름·코드와 처리 이유를 확인합니다. 입력(`editinput`)·전처리(`editprocess`) 정규식, 시작·입력·요청 트리거, Lua·JS 콜백, 모듈 JS·MCP는 아직 지원하지 않아 전송을 막습니다. **이 모듈의 요청 관련 미지원 처리를 제외**를 직접 선택하면 해당 처리를 생략할 수 있습니다. Lua·JS 코드 트리거는 수동·표시·출력으로 지정돼 있어도 여러 콜백을 등록할 수 있어 일괄적으로 무관하다고 처리하지 않습니다.
5. **토글 설정**에는 프리셋과 선택 모듈의 정의를 합쳐 표시합니다. 같은 키·형식·선택지는 한 값으로 공유하고 형식이 다르면 충돌을 표시합니다. 본체의 현재 토글 값은 복사하지 않으며 공방에서 값을 정합니다. 로어북 블록 또는 `{{lorebook}}`이 있는 블록에서 모듈 자료를 사용합니다. 포함할 위치가 없으면 전송을 중단합니다.
6. **전송 내용 → 모듈별 포함·제외 결과**에서 실제 반영 여부를 확인합니다. 이 화면은 현재의 직접 요청·프리셋 요청 모드를 따릅니다. 직접 요청 모드에는 모듈을 적용하지 않습니다. `moduleenabled`는 선택 모듈의 namespace를 조회하고 `moduleassetlist`는 에셋 이름 목록만 반환하며 파일을 읽거나 렌더링하지 않습니다.

출력(`editoutput`)·표시(`editdisplay`) 정규식은 리스 채팅 응답·화면의 후처리이므로 BB의 구조화된 JSON 응답과 수정안에 적용하지 않고 전송도 막지 않습니다. 배경 코드와 일반 수동·표시·출력 트리거도 BB에서 실행하지 않으며 내역에 `not-applicable`로 기록합니다. 빈 IN 정규식도 네이티브처럼 실행하지 않습니다. 프리셋에 들어 있는 정규식도 같은 기준으로 분류하며 **참고자료 → 프리셋 정규식 처리 내역과 원문 확인**, **전송 내용 → 프리셋 정규식 처리 결과**에서 볼 수 있습니다. 규칙 유형을 확인할 수 없으면 차단을 유지합니다. 기존에 저장한 명시적 제외 설정은 유지합니다.

선택 모듈은 공방 안의 사본으로 저장합니다. 본체의 모듈 활성화·캐릭터·모듈 내용은 변경하지 않습니다. 본체에서 수정한 모듈은 선택창을 다시 열어 적용하면 갱신되며, 내용이 바뀌면 해당 모듈의 제외 설정을 초기화해 다시 검토하게 합니다. 프리셋을 새로 가져와도 선택 모듈과 모듈 토글 값은 유지합니다. 모듈 선택은 최대 100개·데이터 합계 32MiB·로어북 합계 3,000개이며 프리셋과 합친 토글은 최대 300개입니다. 기존 요청 문자 수 상한도 적용합니다.

## 현재 검증 범위

정식 출시 버전은 **1.0.0**입니다. 모바일 수정 빌드를 기반 소스로 역동기화했습니다. 자동 검증 142개, 실제 Edge에서 모의 API를 연결한 UI 검증 26개, v0.4.15 역동기화 시 모바일 원본과 변경 구현 정규화 비교 35개를 통과했습니다. 숨겨진 `srcdoc` iframe·투명 body·CSP, 19개 본문 배치 조건, 재열기와 프롬프트·모듈 선택창, 바이너리 프리셋 가져오기·설치 모듈 선택·토글·로어북·실제 전달 메시지를 확인했습니다. 출력 규칙의 단계 구분, `user_input` 조건문, JSON 출력 예시와 OOC·코드 펜스·앞뒤 설명 제거를 검증했습니다. JSON 문자열 안의 코드·줄바꿈·중괄호 보존, 복수 응답·손상된 JSON 거부, 프리필 유지, 기존 제안 검토·명시적 적용 흐름도 확인했습니다. 전체 사용자 프리셋·실제 설치 모듈은 아직 검증하지 않았습니다. 기준 소스는 RisuAI `f50b5942…`, RisuBard `e5412a48…`이며, 사용자의 실제 설치 버전과 동일하다고 가정하지 않습니다.

**실제 RisuBard의 LLM 호출, Lua·상황 선택 단추 실행, 강제 종료 후 복구는 아직 확인하지 못했습니다.** 저장 API 완료와 디스크·동기화 반영 시점은 다를 수 있습니다. 설치 후 실제 환경에서 확인해야 합니다.

정규식 테스트는 RE2JS 공통 문법을 사용합니다. 역참조·전방 탐색, 지원하지 않는 플래그는 테스트를 거부하고 원고 편집은 유지합니다. CBS·실제 채팅 상태를 실행하지 않으므로 `{{data}}` 등 매크로는 문자 그대로 표시될 수 있습니다. 패턴 1,024자 / 입력 65,536자 / 매칭 1,000개 / 출력 1MiB 한도를 표시합니다.

charx 입력은 100MiB, 압축 해제는 200MiB 이하입니다. 별도 모듈 에셋과 지원하지 않는 URI 형식은 오류를 표시합니다. HTTP(S)·ccdefault:·파일이 없는 embeded:// 참조는 메타데이터로 보존하며 외부에서 자동 다운로드하지 않습니다. 내보낼 때 해당 참조를 안내하고, 원본 내장 파일을 확보하지 못한 항목은 이미지 표시를 보장하지 않습니다. 카드 가져오기로 저수준 실행 권한을 자동 허용하지 않습니다.

## 공통 텍스트 부분편집 · v0.4.0

v0.4.3에서는 아래의 엄격한 원문 매칭에 더해 일부 일반 문장 필드에 사용자 구간 선택을 제공합니다. 현재 동작은 아래 v0.4.3 절을 참고하세요.

기존 원고의 텍스트 수정에는 완성 문자열 대신 다음 값을 사용할 수 있습니다. 예를 들어 기존 CSS에서 색상 선언 한 곳만 바꿉니다.

```json
{
  "schemaVersion": 2,
  "task": "regex",
  "data": {
    "upsert": [{
      "ref": "r0",
      "rule": {
        "out": { "edits": [{ "before": "color: #fff;", "after": "color: #ddd;" }] }
      }
    }],
    "remove": []
  }
}
```

- 적용 대상: 설명·첫 메시지·시작 상황의 text, 로어북 comment/key/secondkey/content, 정규식 comment/in/out, Lua comment/code, 기존 초기 변수의 각 값. 설계 대화의 changes에도 같은 형식을 사용합니다.
- before는 비어 있지 않은 원문이며 공백·줄바꿈까지 정확히 한 곳에 일치해야 합니다. 여러 곳에 일치하면 주변 문맥을 더 포함해야 합니다. 정규식 치환이나 유사 매칭은 하지 않습니다.
- 한 필드의 edits는 1~100개입니다. 모든 구간을 요청 당시 원문에서 찾고, 겹침·불일치·중복이 하나라도 있으면 제안 전체를 거부합니다. 앞 수정의 결과를 다음 before로 사용하지 않습니다.
- 삽입은 기존 문맥을 before로, 문맥과 추가 내용을 after로 지정합니다. 삭제는 빈 after 문자열을 사용합니다. 줄 번호는 적용 위치가 아닌 검토용 표시입니다.
- 검토 화면은 변경 구간·필드와 기존/수정 후 줄 번호를 보여 줍니다. Lua·CSS를 실행하거나 언어 문법을 완전히 검사하는 기능은 아닙니다. 원고가 바뀐 뒤의 오래된 제안도 기존처럼 거부합니다.
- 새 항목과 빈 필드의 첫 작성, 명시적인 전체 재작성은 기존 완성 문자열 형식을 사용합니다. 기존 Lua는 ref와 code 또는 comment만 보내면 생략한 값은 보존됩니다. 새 Lua는 ref:null, comment, code가 모두 필요합니다. 설정값(type/mode/flag/불리언/숫자), 대화 reply와 choices 안내 정보는 기존 형식을 사용합니다.
- 자동·수동 저장에는 완성 코드로 확장하지 않은 수정안을 보관합니다. 적용 시 다시 검증합니다. 실제 변경이 없는 응답은 적용할 제안을 만들지 않습니다. 실패한 부분편집을 자동으로 전체 교체하거나 재요청하지 않습니다.
- 저장본 외곽의 schemaVersion은 1로 유지합니다. LLM 응답은 2를 안내하며 기존 버전 1의 완성 문자열 응답·저장된 제안도 계속 읽습니다. 부분편집을 버전 1로 보내면 거부합니다. 버전 2 수정안을 포함한 저장본은 이전 BB 버전으로의 복원을 보장하지 않습니다.
- 저장한 사용자 프롬프트는 유지합니다. 새 출력 계약과 작업별 부분편집 예시는 기존 OUTPUT_FORMAT 자리에 전달됩니다. 출력 토큰 절감은 모델이 구간 수정 형식을 따를 때 발생하며, 판단에 필요한 원문 입력을 자동으로 줄이는 기능은 아닙니다.

## JSON 응답 형식과 잔여물 제거

- 새 응답의 `schemaVersion`은 숫자 `2`, `task`는 선택한 작업 ID, `data`는 작업별 허용 필드만 사용하도록 안내합니다. OOC 제목·코드 펜스·JSON 밖 설명을 금지하고, 대화·Markdown·코드는 해당 문자열 값 안에 넣도록 지시합니다.
- 설계 대화는 `reply`와 빈 `changes: []`를 기본으로 합니다. 대화만 하는 예시와 명시적으로 수정안을 만드는 예시를 분리하고, 다른 작업에도 해당 JSON 예시를 제공합니다. **프롬프트 → JSON 응답 형식과 예시**에서 확인할 수 있습니다.
- 출력 형식은 기존 `<<OUTPUT_FORMAT>>` 자리로 전달하므로 저장한 사용자 템플릿에도 새 예시가 반영됩니다. 사용자 템플릿과 프리셋의 프리필을 자동으로 덮어쓰지 않습니다. 시스템 기본 문안까지 갱신하려면 해당 작업의 **기본값으로 초기화**를 사용하세요.
- 응답에 `## OOC Response`, Markdown 코드 펜스, 앞뒤 설명이 붙으면 완성된 JSON 객체를 찾아 스키마 검증 후 사용합니다. 문자열 안의 따옴표·역슬래시·중괄호를 구분하므로 원고 안의 Markdown·HTML·Lua·JSON 예시는 보존합니다. 성공한 응답의 바깥 잔여물은 대화나 수정안에 넣지 않습니다.
- JSON 내부 문법·필드·작업 종류·참조는 계속 검증합니다. 유효한 응답이 여러 개면 임의로 고르지 않으며, 배열이나 중첩 포장 안의 객체를 임의로 꺼내지 않습니다. 손상된 JSON을 자동 수리하지 않고 기존 1MiB 응답 상한을 유지합니다. 제안은 기존처럼 사용자가 검토하고 적용합니다.

## 개발

```powershell
npm ci
npm run build
npm test
node tools/verify-browser.mjs
```

브라우저 검증은 Windows의 설치된 Edge를 기본으로 사용합니다. 다른 실행 파일은 `WORKSHOP_BROWSER` 환경 변수로 지정할 수 있습니다. 결과와 소스 검증은 `verification/`, 화면 캡처는 `artifacts/`에 있습니다.

유지보수용 소스는 `src/`에 나뉘어 있고 배포 시 하나의 JS로 합쳐집니다. DUSK는 편집 편의성을 검토하는 참고 자료로 사용했으며 소스와 화면을 복제하지 않았습니다. 포함한 외부 라이브러리의 고지는 `THIRD_PARTY_NOTICES.txt`와 배포 JS에 있습니다.

프리셋 어댑터는 RisuBard의 [파일 입출력](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/storage/database.svelte.ts), [v2 조건·토글](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/promptV2.ts), [프롬프트 조립](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/process/index.svelte.ts)을 대조했습니다. 순수 조건·토글 함수를 수정해 사용하고 UI는 본체 저장소에 의존하지 않도록 작성했습니다. 해당 코드의 GPL 조건에 따라 프로젝트와 배포물은 **GPL-3.0-only**로 제공하며 전문은 `LICENSE`와 배포 JS에 포함합니다. 배포 JS를 재배포할 때 대응 소스·빌드 파일과 라이선스도 함께 제공하세요.

CBS 호환성 보완은 [블록 파서](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/parser/parser.svelte.ts)와 [RPN 계산](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/process/infunctions.ts)을 대조·수정해 사용합니다. 테스트의 공식 함수 발췌본은 `tests/fixtures/risubard-cbs-reference.ts`이며 배포 JS에는 들어가지 않습니다.

설치 모듈은 [모듈 데이터·ID/namespace 조회](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/process/modules.ts), [DB 조회 허용 항목](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/plugins/plugins.svelte.ts), [API v3 조회](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/plugins/apiV3/v3.svelte.ts)를 확인했습니다. 네이티브 모듈의 전체 실행 파이프라인 이식은 포함하지 않습니다.

단계 구분은 [정규식 모드](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/process/scripts.ts), [트리거 실행 시점](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/process/triggers.ts), [Lua 편집 콜백](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/process/scriptings.ts)을 대조했습니다. `user_input`의 정의 여부는 [공식 CBS 목록](https://github.com/rpaddict/RisuBard/blob/e5412a4878ae3a0073ffce8e06aed8f288dd9c53/src/ts/cbs.ts)과 블록 파서의 미정의 표기 처리에 근거합니다.
